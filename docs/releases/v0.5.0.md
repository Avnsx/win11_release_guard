# v0.5.0 Release Notes

Purpose: document the concrete `0.5.0` release state for maintainers, release managers, and future agents. Source truth for new work remains the current code, tests, workflows, `pyproject.toml`, README, docs, local wiki source, and `AGENTS.md`.

| Item | Current state |
| --- | --- |
| Package/program version | `0.5.0` from `pyproject.toml` and `win11_release_guard.version.package_version()` |
| Package name | `win11_release_guard` |

`0.5.0` makes the client runtime portable. The default policy cache is no
longer a permanent JSON file under `%LOCALAPPDATA%\win11_release_guard\`; it is
one compact, atomically written record in the operating-system temp directory,
so a run on a managed machine leaves no permanent directory behind. Operators
and embedders get explicit state controls: `--state-dir`, `--stateless`,
`--purge-state`, and `--show-state`, the matching
`WIN11_RELEASE_GUARD_STATE_DIR`, `WIN11_RELEASE_GUARD_STATELESS`, and
`WIN11_RELEASE_GUARD_CACHE_FILE` environment variables, and the `describe_state`,
`purge_state`, and `read_state_bytes` API. `--output` is now written atomically
as well. On-disk state stays an optimisation only: no signed verdict,
`required_baseline_build` selection, `/api/v1` contract, Source Diagnostics
issue-sync rule, WUA-secondary behavior, or 14-day baseline-update notice window
changed.

## Portable Default State

The default cache is a fixed 50-byte little-endian header plus one
`zlib`-deflated body holding the signed policy bytes and the detached
signature, written to the operating-system temp directory. The stored policy and
signature bytes round-trip byte-identically, so the Ed25519 signature still
verifies from cache. The format is a storage choice, not a confidentiality
mechanism, and the record layout is documented in
[Configuration](https://avnsx.github.io/win11_release_guard/wiki/Configuration/).

`--cache-file` keeps its previous transparent behavior: an explicit path still
selects the legacy `policy.json` plus `.sig` pair, now supplied by default from
`WIN11_RELEASE_GUARD_CACHE_FILE` when that variable is set.

## Operator And Embedder State Controls

`--state-dir DIR` moves the record, `--stateless` runs the compliance check with
no state read or write, `--show-state` reports the resolved location and record
metadata, and `--purge-state` removes it. `--purge-state` and `--show-state`
deliberately ignore `--stateless` so a fleet that normally runs stateless can
still inspect and clear what an earlier stateful run left behind. Embedders call
`describe_state`, `purge_state`, and `read_state_bytes` instead of the CLI.

`--diagnose-config` now reports `cache_file` as the effective runtime state
location, or a configured `--cache-file`, and `null` when the run is stateless,
alongside `state_layout`, `state_path`, `state_dir`, `state_dir_source`,
`stateless`, `stateless_source`, `cache_file_source`, and `state_format_version`.

## Atomic Writes And Self-Healing

State, the optional Windows Update cookie cache, the legacy JSON cache pair, and
`--output` are written through one atomic staging-file and `os.replace`
primitive, so an interrupted run cannot leave a half-written file or an empty
cache directory behind. `--output` keeps a single in-place fallback for a report
file another process holds open; its failure message names the path and the
underlying reason and the exit code stays `2`. Because those files are now
written as bytes, they use LF line endings on every platform.

A verified remote policy is no longer discarded when its cache write fails: the
run proceeds on the verified policy and records one `cache_write_failed` source
problem. An unusable record self-heals on the next run, and a record is removed
only at a path the tool derived itself after confirming its magic bytes, so a
foreign file at the same path is never deleted.

The signed bundled production policy and detached signature are not regenerated by
this version bump.

## Unchanged Verdict Boundaries

- Signed public policy JSON plus detached signature remains the compliance verdict authority.
- On-disk state is an optimisation only; it never changes the verdict or the exit code.
- Local Windows labels, WUA, Panther/setup logs, DISM, Event Logs, and Source Diagnostics remain diagnostic evidence.
- 25H2 remains the existing-device broad-fleet target.
- 26H1 remains excluded for existing-device targeting.
- `/api/v1` policy, signature, and manifest aliases stay backward-compatible.
- Notice Source Diagnostic events remain dashboard-only and are not GitHub-Issue-syncable.
- The baseline-update notice is informational dashboard output only, visible for 14 days.
