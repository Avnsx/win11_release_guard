# v0.4.0 Release Notes

Purpose: document the concrete `0.4.0` release state for maintainers, release managers, and future agents. Source truth for new work remains the current code, tests, workflows, `pyproject.toml`, README, docs, local wiki source, and `AGENTS.md`.

## Scope

| Item | Current state |
| --- | --- |
| Package/program version | `0.4.0` from `pyproject.toml` and `win11_release_guard.version.package_version()` |
| Package name | `win11_release_guard` |
| Runtime identity | `win11_release_guard/0.4.0` for runtime user-agent, generator identity, and WUA client application ID |
| Python support | `>=3.10` with classifiers for 3.10, 3.11, 3.12, 3.13, and 3.14 |
| CI compatibility gate | `ci.yml` tests Ubuntu and Windows across Python 3.10–3.14 without `continue-on-error` |
| API compatibility | Policy `schema_version` remains `1`; public `api_version` remains `v1` |
| Verdict model | Unchanged: signed public policy JSON plus detached signature is the compliance authority |

`0.4.0` reads Windows 11 release history, preview and out-of-band builds, and
support articles from Microsoft's Windows 11 servicing index, covering every
serviced Windows 11 lane in a single small request. Support-article link
validation and MSRC CVRF security classification are active, and security
evidence names the affected Microsoft products directly instead of showing
opaque numeric identifiers. Local build and edition checks read Windows
details natively on Windows instead of starting a PowerShell process.
Administrators can optionally enable a Windows Update offer probe for extra
corroborating current-offer evidence; it never changes the signed compliance
verdict. No signed verdict, `required_baseline_build` selection, `/api/v1`
contract, Source Diagnostics issue-sync rule, WUA-secondary behavior, or the
14-day baseline-update notice window changed.

## Servicing Index Source

Release history, preview and out-of-band build detection, and support
article discovery come from Microsoft's Windows 11 servicing index. Every
serviced Windows 11 lane is covered by that single source.

## Support Article Validation And MSRC Product Names

Support article links are checked against the current Microsoft article
before publishing, so a stale or dead link is caught rather than shipped.
MSRC CVRF security evidence names the affected Microsoft products alongside
the exact-KB security match, instead of showing opaque numeric product
identifiers.

## Native Local Windows Reads

Local build, edition, and architecture details are read directly on Windows
through the registry and native Windows APIs, without starting a PowerShell
process. Local checks complete faster on Windows hosts. The resulting
compliance verdict is unchanged.

## Optional Windows Update Offer Probe

An optional, off-by-default Windows Update offer probe can be enabled to
attach corroborating current-offer evidence at notice severity. Enabling it
never affects the signed compliance verdict.

## Outbound Request Handling

Requests to Microsoft sources share one HTTP client with consistent headers,
response decompression, bounded response reads, retry with backoff, and
conditional requests.

## Release Gate Result

Local `0.4.0` gates pass `compileall`, identity/version/action audits, the
full pytest suite, signed fixture generation, secret scanning, clean archive
export and validation, and the live `--check-policy-source` /
`--check-public-pages` checks. The tagged release in
[docs/tagged-release-lane.md](../tagged-release-lane.md) reruns the full
deployment gate.

## Unchanged Verdict Boundaries

- Signed public policy JSON plus detached signature remains the compliance verdict authority.
- Local Windows labels, WUA, Panther/setup logs, DISM, Event Logs, and Source Diagnostics remain diagnostic evidence.
- 25H2 remains the existing-device broad-fleet target.
- 26H1 remains excluded for existing-device targeting.
- `/api/v1` policy, signature, and manifest aliases stay backward-compatible.
- Notice Source Diagnostic events remain dashboard-only and are not GitHub-Issue-syncable.
- The baseline-update notice is informational dashboard output only, visible for 14 days.
